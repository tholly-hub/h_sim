# 【Phase 1】競馬シミュレーションエンジン環境構築・データ生成 実装計画

`markdown.txt` の仕様書に基づき、競馬シミュレーションエンジンの基盤となる **【Phase 1】** の実装計画を策定しました。

---

## 1. プロジェクト全体の把握要約

- **目的**: 遺伝アルゴリズム（ポリジーン・ミオスタチン・母系遺伝）に基づく長期馬群シミュレーションエンジンの構築。
- **ターゲット環境**: Mac / Windows 両対応（Python 3.10+、PyQt6、`pathlib`）。
- **データ管理**: SQLite（Google Drive等の同期フォルダへ配置・保存先変更可能）。
- **全体フェーズ**:
  - **Phase 1**: データベース環境・パス設定 & 競走馬・生産牧場・馬主モジュール（← 現在着手）
  - **Phase 2**: 交配・遺伝アルゴリズム & 繁殖・牧場・馬主の動的分化・世代交代
  - **Phase 3**: 番組表登録 & レースシミュレーション・タイム計算エンジン
  - **Phase 4**: UI / GUIデータ可視化（PyQt6）

---

## 2. Phase 1 の実装スコープ

1. **クロスプラットフォーム パス・設定管理 (`src/core/config.py`)**:
   - `pathlib.Path` によるOS非依存のパス設計（Windowsのドライブ文字やMacのPOSIXパスに対応）。
   - 設定ファイル（JSON等）または環境変数によるデータベースファイル保存先（`horse_racing_sim.db`）の変更・読み込み機能。
2. **SQLiteデータベース管理 & DDL (`src/db/database.py`, `src/db/schema.py`)**:
   - `breeders`（生産牧場: 初期50場、規模、評判、資金、通算成績等）
   - `owners`（馬主: 初期100人、冠名、資金、所有頭数、通算成績等）
   - `horses`（競走馬: 基本情報、MSTN型、ポリジーン5能力、成長型、加齢、生涯獲得賞金、収得賞金等）
   - `sires` / `dams`（種牡馬・繁殖牝馬テーブルまたは競走馬テーブルと連携した繁殖管理）
   - `races` / `results`（Phase 3を見据えた将来拡張用テーブルスキーマ）
3. **馬名自動生成ロジック (`src/generators/name_generator.py`)**:
   - 馬主固有の冠名（Prefix）＋単語/血統由来名。
   - カタカナ9文字以内制約（JRA馬名ルール準拠）と重複チェック。
4. **初期データ生成・シードモジュール (`src/generators/initializer.py`)**:
   - 初期50牧場（各場10〜20頭程度の繁殖牝馬を割り当て可能にする初期設定）。
   - 初期100馬主（それぞれユニークな冠名を設定）。
   - 初期繁殖群（種牡馬50〜100頭、繁殖牝馬500〜1,000頭）および初期現役馬の能力パラメータ生成（$\mu=50.0$、MSTN型付与）。
5. **Phase 1 動作検証スクリプト (`tests/verify_phase1.py` / `main.py`)**:
   - DB作成から初期データ投入、クエリ検証、馬名重複や制約チェックを一気通貫でテスト。

## 4. 検証計画

- **自動テスト**:
  - `pytest` または `unittest` により、以下を自動検証：
    1. パス解決がWindows/Macでエラーなく動作すること。
    2. SQLiteテーブルが外部キー制約を含め正常に生成されること。
    3. 50牧場、100馬主が生成され、冠名がすべてユニークであること。
    4. 自動生成された馬名がすべてカタカナ9文字以内であり、DB内で重複しないこと。
    5. 初期の競走馬・種牡馬・繁殖牝馬の能力値が要件（平均50.0、0〜100の範囲内、MSTN遺伝子型）を満たしていること。
